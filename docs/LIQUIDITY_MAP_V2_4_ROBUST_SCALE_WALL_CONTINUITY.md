# Liquidity Map V2.4：稳健 24h 色阶与墙连续性修复

## 结论

本版本修复两个后端问题，不是单纯修改 UI：

1. 某些日期全浅、某些日期全深；
2. 肉眼明显属于同一堵墙，却被识别成多个生命周期。

不需要重新 prebuild Books 或 Liquidity Map NPZ。

---

## 一、颜色差异过大的真实原因

V2.3 确实使用了过去 24 小时滚动窗口，但参考值采用：

```text
过去24小时内出现过的单个最大 $1 价格格挂单量
```

这会导致一个只存在一帧的极端巨单，把随后 24 小时的色阶上限抬得很高：

```text
瞬时极端单出现 -> 随后普通挂单全部偏浅
极端单滚出24h窗口 -> 色阶突然下降 -> 普通挂单整体变深
```

因此问题不是“没用24小时”，而是“24小时绝对最大值太脆弱”。

### V2.4 新参考值

每个已完成快照先计算所有买卖价格格深度的 P99，然后取这些 P99 在过去 24 小时内的滚动最大值：

```text
snapshot_high(t) = 当前完成快照所有价格格深度 P99
reference(t)     = 过去24h snapshot_high 的最大值
ratio(t, p)      = 当前价格格深度 / reference(t)
```

优势：

- 单个一闪而过的巨大价格格不会压白随后一天；
- 一大片持续深色的真实高流动性区域仍会抬高参考值；
- 所有计算只使用当前和过去的已完成快照；
- 前端颜色与墙检测继续共用同一 ratio。

参数 `每帧高位参考分位数` 默认 99，可设为 100 复现旧版绝对最大值，仅建议诊断时使用。

## 二、同一堵墙被拆成多块的真实原因

V2.3 有三处会让同一堵墙反复生成新 wall_id：

### 1. 先聚合 30% 主体格，再补 15% 连接格

如果多个深色核心之间由 15%-30% 的浅/中等色块连接，旧代码会先把深色核心拆开，后面的连接格无法重新把它们合并。

V2.4 改成：

```text
先用 15%+ 支撑层形成区域
再在区域内验证 30%+ 主体格和 50%+ 核心格
```

这更符合“深色核心 + 浅色连接层共同形成一大片墙”的视觉定义。

### 2. POINT 与 MAIN 切换会强制断开

同一价格区域可能暂时只有一个深色点，随后邻近价格挂单加厚，从 POINT 变成 MAIN。旧代码将类型变化视为不同墙。

V2.4 允许同一固定价格区域在 POINT / MAIN 之间因果切换，类型是墙的当前状态，不再是墙的身份。

### 3. 只允许消失 2 帧

15 秒精度下，旧版只允许约 30 秒变浅。真实墙短暂变浅几分钟后恢复时，会被结束并重新创建。

V2.4 默认允许同一稳定价格区域短暂变浅 10 分钟：

```text
正常检测到 -> STABLE/PERSISTENT/MAJOR
短暂低于阈值 -> FADING
重新出现且位置稳定 -> 恢复原 wall_id
超过容忍时间 -> 墙死亡
```

FADING 阶段用虚线连接，不代表当前仍可用于挂单，只代表机器仍在追踪同一堵墙的身份。

---

## 三、仍保持的安全边界

- 墙边界只使用当时已知快照，不用未来范围回写过去；
- 墙中心使用近期已完成观察的中位位置做锚点；
- 持续迁移的墙不会无限跟踪，超过中心漂移限制会创建新墙；
- FADING 状态不能直接视作可交易有效墙；
- 本版本仍是人工审计阶段，禁止直接用于实盘。

---

## 四、建议初始参数

```text
挂单量参考窗口：24小时
每帧高位参考分位数：99
最深核心：50%
主墙主体：30%
主墙连接：15%
允许短暂变浅：10分钟
跨帧最小重叠：20%
最大中心移动：3个价格格
```

先重点审计：

```text
2026-01-25 09:00 附近
```

观察原来四段墙是否被统一为同一个 wall_id；暂时变浅处应显示为虚线连接，而不是四个无关黄色框。
