按“**最能减少走错方向 + 最快看到真实效果 + 最终能实盘**”排序，我建议这样推进。

# 总顺序

## P0：统一市场状态基础架构

**必须第一个做。**

先建立：

```text
src/market_state/
    models.py
    data_bundle.py
    causal_alignment.py
    feature_engine.py
    state_engine.py
    transitions.py
    data_quality.py

analyze_tool/plugins/
    market_state_map.py
```

先统一：

* 状态快照数据结构
* 所有数据的 `available_time`
* raw trade、trade bar、range bar、高周期 K 线的对齐方式
* 回测、研究、可视化共用同一个状态计算核心

否则后面每个研究脚本都会再写一套状态定义，最后无法组合，也无法迁移实盘。

高周期和衍生数据必须按真实可用时间对齐，不能按照 bar 开始时间提前使用。

**完成标准：**

```text
给任意时间点，能够生成一份因果 MarketStateSnapshot
analyze_tool 能显示状态，但暂时不要求状态有交易价值
```

---

## P1：趋势质量与市场结构状态

这是第一项正式研究。

先研究：

```text
方向
趋势强度
路径效率
趋势持续时间
回撤深度
趋势成熟度
滚动区间位置
高低点结构
```

先区分：

```text
有序上涨
无序上涨
有序下跌
无序下跌
平衡震荡
```

为什么先做：

* 几乎所有策略都受趋势环境影响
* 数据最可靠
* 最容易因果实现
* 可以立即解释现有 Momentum、Reclaim、Low Sweep 为什么有时有效、有时失效

**可视化：**

```text
K 线背景状态色带
trend_score 曲线
orderliness_score 曲线
trend_age
区间位置
```

---

## P2：波动率与市场活动状态

第二个做：

```text
实现波动率
ATR 分位数
价格路径长度
单位时间 Range Bar 数量
Trade Bar 生成速度
成交笔数
成交额
成交频率变化
```

区分：

```text
沉寂
波动压缩
正常
波动扩张
极端冲击
```

它非常重要，因为：

```text
趋势 + 低波动
趋势 + 波动扩张
震荡 + 低波动
震荡 + 极端波动
```

是完全不同的交易环境。

**P1 + P2 做完后，已经可以得到第一版肉眼可用地图。**

## P3：主动订单流状态

第三个做，也是最可能产生新 edge 的部分。

使用现有 raw trade / trade bar：

```text
主动买卖金额
delta
CVD
买卖持续性
订单流加速度
大单方向
成交频率
连续主动买入或卖出时间
```

不能只看一根 bar，需要研究：

```text
1分钟
3分钟
5分钟
15分钟
30分钟
```

输出：

```text
flow_direction
flow_strength
flow_persistence
flow_acceleration
large_trade_alignment
```

区分：

```text
持续主动买入
持续主动卖出
订单流平衡
买压增强
卖压增强
订单流衰竭
```

## P4：价格冲击与吸收状态

这是第四个做，但属于核心 edge 层。

把订单流和价格响应结合：

```text
主动卖出很多，价格是否真的下跌
主动买入很多，价格是否真的上涨
单位成交额造成多少价格移动
冲击后价格恢复速度
价格与 CVD 是否背离
同一位置是否反复被测试
```

输出：

```text
buy_impact_efficiency
sell_impact_efficiency
buy_absorption_score
sell_absorption_score
exhaustion_score
recovery_score
```

区分：

```text
卖压有效
卖压被吸收
买压有效
买压被吸收
双方激烈但价格平衡
流动性真空式移动
```

这是以后研究：

```text
恐慌卖压 → 吸收 → reclaim
主动买入 → 无法上涨 → 顶部派发
```

的基础。

---

## P5：关键位置与流动性结构

第五个做。

整合现有：

```text
swing high / low
first sweep
repeated test
reclaim
HTF respected level
滚动高低点
成交密集区
前期突破位置
```

状态不是简单输出“支撑位”，而是：

```text
正在接近
首次测试
重复测试
已经扫过
快速拒绝
接受并停留
重新收复
位置已经被消耗
```

这一层必须在趋势、波动和订单流完成后再做，否则容易重新退化成单纯看 K 线形态。

## P6：可交易性与执行风险

第六个做，但在正式回测前必须完成。

研究：

```text
成交是否足够
价格是否跳跃
预期滑点
流动性是否异常
状态是否切换太快
数据是否断流
特征是否过期
状态置信度
```

输出：

```text
tradeability_score
execution_risk_score
data_quality_score
```

有些状态方向判断正确，但由于波动和流动性太差，实际仍不应该下单。

统计每种状态：

这一阶段只验证：

```text

```

不直接优化收益。

---

## P8：状态转移研究

重点研究：

```text
压缩 → 扩张
震荡 → 趋势
有序趋势 → 无序趋势
趋势 → 衰竭
恐慌 → 继续崩跌
恐慌 → 吸收
吸收 → reclaim
reclaim → 恢复或再次失败
```

我认为最终最可能产生交易价值的，不是静态状态，而是这些**状态转移过程**。

## P10：统一 Portfolio 状态路由回测

最终状态地图输出：

```python
StrategyPermission(
    strategy_id="low_sweep",
    enabled=True,
    risk_multiplier=0.6,
    confidence=0.78,
    reason="sell_absorption_after_panic",
)
```

状态层不直接下单，只决定：

```text
哪个策略可以工作
哪个策略应该停止
使用多少风险
执行条件是否安全
```

回测默认必须包含完整买卖成本 0.11%，再测试手续费、滑点和延迟翻倍。
